Kolmogorov Complexity —
The Deepest Definition of Information

The complexity of a string is the length of the shortest program that outputs it. This deceptively simple idea unlocks the deepest definitions of randomness, incompressibility, and information that computer science has ever produced — and in doing so, reveals something unsettling: the theory is uncomputable from the inside.

Umakant Kunal
MSc Computer Science

Consider the number 3.14159265358979323846... You could describe it by listing all the digits. But you could also write: "compute pi to N decimal places." That second description is vastly shorter — a handful of words versus billions of symbols — yet it uniquely and completely specifies the same information. Now ask: what is the shortest possible description of this number? What about a truly random string of a billion bits — can it be compressed at all?

These questions sound informal, almost literary. But in the 1960s, Andrey Kolmogorov, Ray Solomonoff, and Gregory Chaitin independently discovered that they have precise, rigorous answers. Kolmogorov complexity formalises the notion of the shortest description: the complexity of a string is the length of the shortest computer program that outputs it and halts. What follows from this single definition is extraordinary — a complete mathematical theory of randomness, a formalisation of Occam's razor, a connection to Shannon entropy, and a proof that the very concept at the heart of the theory is forever beyond computational reach. This is arguably the deepest result in all of theoretical computer science, and it lives almost entirely outside the standard curriculum.

THE DEFINITION

Fix a universal programming language — a Turing-complete model of computation. It could be Python, a Turing machine, a cellular automaton, or any formal system powerful enough to simulate any other. For a string x, the Kolmogorov complexity K(x) is defined as:

K(x) = the length in bits of the shortest program p such that running p outputs x and halts.

More formally: if U is a universal Turing machine, then KU(x) = min { |p| : U(p) = x }, where |p| denotes the length of program p in bits. The minimum is over all programs that produce x as their only output.

A few immediate examples make the concept concrete:

  • K("0000000000...0" repeated 10,000 times) is very small — a program like "print '0' ten thousand times" requires only O(log n) bits to specify, far less than the string itself.
  • K("3.14159265358979...") is small relative to the digits — a short program can compute arbitrarily many digits of π using known series (Machin's formula, BBP, etc.).
  • K(a truly random 1000-bit string) is approximately 1000 — because there is no structure to exploit, the shortest program is essentially "print these exact bits", which itself must encode all 1000 bits.

The third case is the profound one. Most long strings are incompressible — their Kolmogorov complexity is close to their length. There is a simple counting argument: there are 2n binary strings of length n, but only 2n − 1 programs shorter than length n. So at least one string of length n cannot be compressed. In fact, almost all strings cannot be significantly compressed — the compressible ones are a vanishingly small fraction. This is the first hint that randomness is not rare; it is everywhere.

WHY THE LANGUAGE DOESN'T MATTER

An obvious objection arises immediately: K(x) surely depends on which programming language we pick. A program that is short in Python might be long in a Turing machine description, and vice versa. Is Kolmogorov complexity just a property of our arbitrary choice of language, rather than a property of the string itself?

The answer is no, and the reason is the Invariance Theorem — perhaps the most important theorem in algorithmic information theory.

Invariance Theorem: For any two universal programming languages L1 and L2, there exists a constant c(L1, L2) — depending only on the languages, not on x — such that for all strings x:

KL1(x) ≤ KL2(x) + c(L1, L2)

The proof is elegant: since L1 is universal, it can simulate L2. The overhead of that simulation — a fixed interpreter — is the constant c. It never depends on x. Symmetrically, KL2(x) ≤ KL1(x) + c'(L1, L2), so the two complexities differ by at most a constant regardless of how large x grows.

For short strings, this constant matters — different languages can give very different results. But for strings that are megabytes, gigabytes, or longer, the additive constant becomes negligible. In the asymptotic regime that matters for theory, the choice of language is irrelevant. Kolmogorov complexity is a property of the string — a mathematical invariant, not an implementation detail. This is what elevates it from a programming curiosity to a genuine mathematical concept.

"It is possible to introduce the concept of the quantity of information contained in an individual object — a concept free from any probability notions — by considering the shortest program for computing this object." — Andrey Kolmogorov, "Three approaches to the definition of the concept of information quantity" (1965)

RANDOMNESS DEFINED PROPERLY

Here is one of the most remarkable payoffs of Kolmogorov complexity: for the first time in mathematics, we have a rigorous, non-probabilistic definition of what it means for a single string to be random.

A string x is Kolmogorov random (or algorithmically random) if K(x) ≥ |x| − c for some small constant c — that is, if no program significantly shorter than x itself can output x. The shortest description is essentially just the string itself. There is no pattern, no regularity, no compressible structure anywhere. The string cannot be compressed.

Compare this to classical probability theory's approach to randomness. A coin flip sequence is "random" if it came from a fair coin — a statement about the process that generated it, not about the sequence itself. Two sequences, 0101010101... and 0110100110..., have exactly the same probability under a fair coin. But the first is not random in any meaningful sense — it has an obvious pattern. Kolmogorov complexity correctly assigns K("0101...") ≈ O(log n) and K("0110100110...") ≈ n, capturing the intuition that the first sequence is structured and the second is not.

Per Martin-Löf's refinement, a sequence is Martin-Löf random if it passes all effective statistical tests — a condition that turns out to be equivalent to Kolmogorov randomness up to logarithmic terms. This gives us incompressibility as the unifying principle: a truly random string resists every algorithmic pattern-finding strategy simultaneously. Not just some tests. All of them.

Most strings are random. This is counterintuitive but mathematically precise. Of all 2n binary strings of length n, fewer than 2n−c+1 have complexity less than n − c. The highly structured, compressible strings we tend to think about — zeros, pi's digits, Fibonacci sequences — are an infinitesimally small subset of all possible strings. Almost everything is incompressible. Almost everything is random. The strings that have meaning to us are the exceptional ones.

KC IS UNCOMPUTABLE

There is a catch — and it is a profound one. Kolmogorov complexity is not computable. There is no algorithm that, given a string x, outputs K(x). This is not a technical limitation awaiting a better computer or a faster algorithm. It is a fundamental barrier, provably insurmountable.

The proof is a beautiful diagonalisation argument, closely related to — but distinct from — the proof of the halting problem's undecidability.

Suppose, for contradiction, that there exists a program C that computes K(x) for any input x. Now construct the following program B(n):

  1. Enumerate all binary strings in lexicographic order: s1, s2, s3, ...
  2. For each string si, use C to compute K(si).
  3. Output the first si with K(si) > n.

The program B(n) is well-defined: it halts and outputs a string with Kolmogorov complexity greater than n. But here is the contradiction. B(n) itself is a fixed program of some length L (the code for B), plus O(log n) bits to encode n. So the total length of the description is L + O(log n). For large enough n, this is less than n. We have found a short program that outputs a string with high complexity — but Kolmogorov complexity is the length of the shortest such program. Contradiction.

This is sometimes called Berry's paradox in mathematical form: "the smallest positive integer not definable in fewer than thirteen words" is itself defined in twelve words. The paradox is not wordplay; it is pointing at a genuine incompleteness in any sufficiently powerful formal system that tries to describe its own complexity.

The connection to the halting problem is not coincidental. If we could compute K(x), we could solve the halting problem — any upper bound on K from a running program would require knowing when to stop searching for shorter programs, which requires knowing if programs halt. The two undecidabilities are deeply intertwined. Both trace back to the same diagonal argument that Gödel, Turing, and Church discovered in the 1930s.

"The halting problem and Kolmogorov complexity are two facets of the same jewel. Both are about the limits of self-reference in formal systems — what a system can know about itself. Neither problem is harder than the other; they are, in a precise sense, the same problem." — Ray Solomonoff, from lecture notes on algorithmic probability (circa 1997)

OCCAM'S RAZOR FORMALISED

William of Ockham's razor — "entities should not be multiplied beyond necessity" — has guided scientific thinking for seven centuries. It says prefer simpler explanations. But what does "simpler" mean, precisely? Shorter in words? Fewer parameters? Less complexity in some intuitive sense? For centuries, this principle resisted mathematical formalisation. Kolmogorov complexity finally provides it.

Solomonoff induction is the result. Given a sequence of observations x1, x2, ..., xn, what is the probability that the next observation is xn+1? Solomonoff's answer: weight each computable hypothesis h (a program that generates the sequence) by 2−K(h) — exponentially down-weighting longer, more complex hypotheses. The Solomonoff prior assigns probability:

P(x) = Σ{p : U(p) outputs x as a prefix} 2−|p|

This is a probability distribution over all computable hypotheses, giving higher weight to simpler ones in exact proportion to their brevity. It is the universal prior — the optimal Bayesian prior over all computable models of the world. If you could compute it, you would have the best possible prediction for any computable process.

The beauty of Solomonoff induction is that it requires no assumptions about the domain. It is domain-agnostic, prior-free in the usual sense, and yet provably convergent: as more data arrives, the universal prior converges to the true distribution faster than any other computable prior (Solomonoff's convergence theorem). In a precise technical sense, it is the ideal scientific reasoner. It embodies Occam's razor not as a heuristic but as a theorem about optimal inference.

The catch is the same as before: because K is uncomputable, Solomonoff induction is also uncomputable. You cannot actually implement the ideal reasoner. You can only approximate it — which is exactly what all of machine learning, Bayesian inference, and scientific model selection are doing, whether they know it or not.

Every compression algorithm is an implicit theory of the world. When gzip compresses a text file, it is exploiting regularities — repeated n-grams, predictable patterns. The regularities it finds are its implicit model of what text looks like. A better compressor encodes a better model. This is not a metaphor. It is a theorem: compression and prediction are formally equivalent. A model that predicts well is a model that compresses well, and vice versa. Minimum description length makes this equivalence explicit and actionable.

CONNECTIONS TO SHANNON ENTROPY

Claude Shannon defined entropy in 1948 as a measure of uncertainty in a probability distribution. For a distribution P over symbols, Shannon entropy is H(P) = −Σ P(x) log P(x). It measures the average information content of messages drawn from that distribution — or equivalently, the theoretical minimum average number of bits needed to encode messages from the source.

Kolmogorov complexity measures something different: not the average information in messages from a distribution, but the specific information in a particular string. No distribution required. No ensemble. Just the string itself.

The relationship between the two turns out to be precise and beautiful. If x is drawn from a computable distribution P, then the expected value of K(x) is approximately equal to Shannon entropy H(P) — up to an additive constant. More formally: E[K(x)] ≈ H(P) + O(1) when x ~ P.

This is not a coincidence. Both quantities are measuring the same underlying phenomenon — the degree of surprise or unpredictability in information — but from complementary perspectives. Shannon entropy looks at the distribution: how uncertain is the source on average? Kolmogorov complexity looks at the instance: how much structure does this particular string contain? Shannon's lens is statistical; Kolmogorov's lens is algorithmic. Together they form a complete picture.

There is a further connection through conditional complexity. The conditional Kolmogorov complexity K(x|y) — the length of the shortest program that outputs x given y as a free input — behaves like conditional entropy: K(x,y) ≈ K(y) + K(x|y). Mutual information I(x;y) = K(x) − K(x|y) behaves like algorithmic mutual information. The entire Shannon information-theoretic framework has an algorithmic shadow that lives at the level of individual strings rather than distributions.

"The minimum description length principle is an attempt to make Kolmogorov complexity practical. Since the universal complexity is uncomputable, we approximate it with real model classes. The philosophy is the same: the best model is the one that most compresses the data." — Jorma Rissanen, "Minimum Description Length Principle" (1983)

MINIMUM DESCRIPTION LENGTH

If Solomonoff induction is the ideal but uncomputable form of the theory, Minimum Description Length (MDL) is its practical, computable cousin. The MDL principle, developed by Jorma Rissanen in the 1970s and 1980s, says: the best model for a dataset is the one that produces the shortest total description of the model and the data given the model.

Formally, given data D and a family of models M, MDL selects the model M* that minimises:

L(M) + L(D | M)

where L(M) is the description length of the model itself, and L(D|M) is the description length of the data under the model (the residuals, the exceptions, the things the model doesn't explain). This is a direct application of Kolmogorov's insight: the total description length is the complexity of the hypothesis plus the complexity of the data given the hypothesis. Minimising it is equivalent to finding the best compression — the most powerful explanation.

The connection to everyday compression is immediate and humbling. A ZIP file is an approximation to Kolmogorov complexity. When you compress a file and it shrinks dramatically, that shrinkage is evidence that the file contained redundancy — structure — that a model could capture. The compression ratio measures how well your compressor understood the data. Better understanding → better model → better compression. This is not merely analogous to MDL; it is MDL, implemented as an algorithm.

The implications for model selection are profound. Overfitting is not a statistical pathology — it is a description-length failure. An overfit model describes the noise in the training data as well as the signal; it has a short L(D|M) but a long L(M). The total description is longer than a simpler model that ignores the noise. Regularisation, cross-validation, Bayesian model averaging — all of these can be understood as approximations to the MDL principle. They are all trying, in different ways, to find the model that best compresses the data. Understanding and compression are, at bottom, the same thing.

THE PHILOSOPHICAL CONSEQUENCES

Kolmogorov complexity is not merely a technical result. It changes what we think computation, information, and science are. Let me trace the largest implications.

Simplicity is mathematically measurable. For centuries, simplicity was an aesthetic criterion — we preferred simpler theories because they were more elegant, easier to teach, less likely to overfit. Kolmogorov complexity makes simplicity quantitative: the complexity of a theory is the length of its shortest formalisation. Two competing theories can be compared not just qualitatively but in bits. Occam's razor becomes a number.

The laws of physics are a compression of observations. Every physical law is a program that generates correct predictions from initial conditions. Newton's laws compress centuries of astronomical data into three short equations. Maxwell's equations compress all of classical electromagnetism into four. General relativity compresses gravitational phenomena that resisted description for millennia. The project of physics — finding laws that explain observations — is, in the Kolmogorov sense, the project of finding the shortest program that generates those observations. A "theory of everything" would be a program of extreme brevity that outputs the observable universe.

Max Tegmark's Mathematical Universe Hypothesis pushes this further: perhaps the universe literally is a mathematical structure — the kind of structure that can be specified by a short program. The apparent fine-tuning of physical constants might reflect the fact that universes with short descriptions are more probable under a Solomonoff-style prior. This is speculative physics, but it is not arbitrary speculation. It follows directly from taking algorithmic probability seriously as a prior over possible worlds.

Algorithmic information theory as a foundation for science. Thomas Kuhn described scientific progress as paradigm shifts — discontinuous jumps between incommensurable frameworks. Solomonoff induction provides an alternative picture: science is Bayesian updating under a universal prior, continuously revising hypotheses as data arrives, always preferring shorter explanations. The two pictures are not incompatible, but the algorithmic one suggests that scientific progress has a direction — toward shorter descriptions of more data. Compression is the metric of understanding.

And then there is the limit — the one that gives the whole enterprise its melancholy edge. KC is uncomputable. The deepest theory of information content is inaccessible from within information-processing systems. We can approximate K from above — by finding programs that output x, we get upper bounds on K(x). But we can never verify that we have found the shortest one. We can never know if we have the simplest explanation. The ideal is real; it is just forever out of reach.

This is Gödel's incompleteness from a different angle. Any formal system powerful enough to describe its own complexity is powerful enough to construct statements it cannot prove. The shortest description of a string cannot be certified as shortest from within the language used to describe it. The map cannot completely describe the territory when the map is part of the territory. The deepest theory of information is, from the perspective of any embedded information processor, an asymptote — approachable but never reached.

I came to Kolmogorov complexity sideways, through a course on computability theory that I initially found dry. The undecidability results felt like accounting — careful logical bookkeeping proving you could not do things you already suspected you could not do. Then we hit the Berry paradox, and something clicked. The undecidability of KC is not a failure of ingenuity. It is a statement about the nature of information itself: no system can fully see its own complexity from the inside. I found that genuinely beautiful, and more than a little vertiginous.

What stayed with me longest was the MDL connection. I had been writing machine learning code for two years at that point — tuning regularisation parameters, agonising over model selection, explaining to myself why early stopping worked. The moment I understood that every compression algorithm is an implicit theory, and every model selection criterion is an approximation to Kolmogorov complexity, the whole discipline snapped into focus. We are all, always, looking for the shortest program. The difference between a good data scientist and a bad one is partly how well they approximate the uncomputable ideal.

The uncomputability does not bother me the way it once did. We navigate by asymptotes all the time. The speed of light is an asymptote for velocity; we still do useful physics at relativistic speeds. Perfect compression is an asymptote for understanding; we still build useful models by approximating it. The ideal is not meant to be reached. It is meant to orient the work.
