P vs NP — The Million
Dollar Question No One
Can Answer

In 2000 the Clay Mathematics Institute listed seven problems worth a million dollars each. One of them is a computer science question. It has been open for over 50 years. Most researchers believe the answer is no. No one can prove it. And the stakes are higher than any prize money.

Umakant Kunal
MSc Computer Science

In the year 2000, the Clay Mathematics Institute published a list of seven unsolved problems, each carrying a prize of one million dollars. The problems were chosen to represent the deepest open questions in mathematics — the Riemann Hypothesis, the Navier-Stokes existence and smoothness problem, the Yang-Mills existence and mass gap. Problems that had resisted the best mathematical minds for decades or centuries.

One of the seven is a computer science question. It asks: does P equal NP? The question is brief enough to fit in a single line. The implications, if resolved in either direction, would reshape cryptography, scientific research, artificial intelligence, and our understanding of what computation is fundamentally capable of. It has been formally open since 1971. The consensus view — held informally but nearly universally — is that the answer is no. No one can prove it.

What follows is an attempt to explain what the question actually asks, why the answer matters so much, and why proving anything at all has turned out to be so extraordinarily hard.

WHAT P MEANS

P stands for Polynomial time. A problem is in P if there exists an algorithm that solves it in time proportional to some polynomial function of the input size. If your input has n elements, the algorithm runs in time proportional to nk for some fixed constant k — whether that is n, n², n³, or n¹⁰⁰. The key feature is that the exponent k stays constant as the input grows.

Why does polynomial time matter? Because it scales. If you double the input size of a polynomial-time algorithm, the runtime grows by at most a polynomial factor. Compare this to exponential-time algorithms, where doubling the input can square or cube the runtime — making problems that take a second with 50 inputs take years with 100 inputs, and longer than the age of the universe with 1000.

The canonical examples of P problems: sorting (merge sort runs in O(n log n), barely above linear), shortest paths (Dijkstra's algorithm runs in polynomial time on a graph), matrix multiplication (the naïve algorithm is O(n³); the Strassen algorithm beats that), primality testing (the AKS algorithm, 2002, proved this is in P). These are all tractable — scale them up and they remain manageable.

The intuition: P = the set of problems we can efficiently solve. Not just in theory but in practice. A polynomial-time algorithm is not always fast in absolute terms — n¹⁰⁰ is technically polynomial but practically useless — but the classification captures something deep about computational structure that has proved remarkably robust.

WHAT NP MEANS

NP stands for Non-deterministic Polynomial time. This name is historically accurate but deeply misleading to anyone encountering it for the first time. NP does not mean "not polynomial." All P problems are also NP problems. NP is a larger class that contains P.

The cleaner way to understand NP is through verification. A problem is in NP if, given a proposed solution — a certificate, a witness, a candidate answer — you can verify whether that solution is correct in polynomial time. Finding the solution may be hard. Checking it is easy.

The canonical examples of NP problems:

  • Boolean Satisfiability (SAT) — given a logical formula with variables that can be true or false, is there an assignment of values that makes the whole formula true? Checking a proposed assignment is easy: plug in the values and evaluate. Finding one is believed to be hard.
  • Travelling Salesman (decision version) — given a set of cities and distances, does a route exist that visits all cities and returns to the start with total distance below some threshold L? Verifying a proposed route is easy: sum the distances. Finding the shortest route is hard.
  • Graph colouring — can the vertices of a graph be coloured with k colours such that no two adjacent vertices share a colour? Verifying a proposed colouring is easy. Finding one is hard.
  • Subset sum — given a set of integers and a target T, does any subset sum to exactly T? Verifying a proposed subset is trivial. Finding it is not.

The alternative, formal definition uses non-deterministic Turing machines — hypothetical machines that can simultaneously explore all possible paths of computation and accept if any path succeeds. A problem is in NP if a non-deterministic Turing machine can solve it in polynomial time. The verification-based definition is equivalent and more intuitive.

"The class NP consists of those problems for which, once we have a solution, we can verify that it is correct in polynomial time. It is not the class of 'hard' problems — it is the class of problems with easily-checkable answers." — Stephen Cook, Turing Award Lecture, 1982

THE QUESTION

The P vs NP question asks: if you can verify a solution quickly, can you always find one quickly?

Stated that way, it almost sounds mundane. A question about algorithms and efficiency. But the consequences of either answer are so vast that it is worth pausing on each separately.

If P = NP: every problem whose solution can be efficiently checked can also be efficiently solved. The entire class of NP problems — SAT, travelling salesman, graph colouring, protein folding, theorem proving — collapses into P. This would mean:

  • Most modern cryptography breaks. RSA, elliptic-curve cryptography, and most public-key systems depend on the assumed hardness of problems like integer factorisation and discrete logarithm — problems believed to be in NP but not in P. If P = NP, these problems have efficient solutions. Every encrypted message becomes decryptable. Every secure channel becomes insecure.
  • Drug discovery and protein folding become tractable optimisation problems. Currently these rely on expensive simulations and heuristics because the underlying combinatorial problem is NP-hard. Efficient algorithms would transform medicine.
  • Mathematical proofs can be found automatically. Proof verification is in NP — given a proof, checking it is polynomial. If P = NP, finding proofs becomes polynomial too. The entire enterprise of mathematics would be computable by machine.
  • Optimisation at every scale — logistics, scheduling, financial modelling, machine learning architecture search — becomes exactly solvable, not approximately heuristic.

If P ≠ NP: the status quo is confirmed. Hard problems are genuinely hard. Cryptography retains its theoretical foundation. Human creativity and insight retain a domain that algorithms cannot automatically replicate. But here is the uncomfortable truth: we have never proved it. After more than fifty years, we still cannot rule out the possibility that some clever polynomial-time algorithm exists for SAT, waiting to be discovered.

P vs NP asks whether P = NP, where P is the class of decision problems solvable in deterministic polynomial time, and NP is the class of decision problems where a proposed solution can be verified in deterministic polynomial time. All P problems are in NP; the question is whether NP ⊆ P — equivalently, whether NP = P. The question was formalised independently by Stephen Cook (1971) and Leonid Levin (1973).

NP-COMPLETE PROBLEMS

Within NP, there is a special subset called NP-complete: the hardest problems in the class. A problem X is NP-complete if (1) X is in NP, and (2) every problem in NP can be efficiently reduced to X. This second condition is the profound one. It means NP-complete problems are, in a precise sense, universal representatives of NP: solve any one of them efficiently and you solve them all.

The first NP-complete problem was identified by Stephen Cook in 1971: Boolean satisfiability (SAT). The Cook-Levin theorem proved that every problem in NP can be efficiently reduced to SAT. If you can solve SAT in polynomial time, you can solve any NP problem in polynomial time. SAT was the first domino.

"I showed that satisfiability is NP-complete. This means that if satisfiability can be solved in polynomial time, then every problem in NP can be solved in polynomial time — and P would equal NP." — Stephen Cook, "The Complexity of Theorem-Proving Procedures," 1971

Within a year, Richard Karp published a landmark 1972 paper demonstrating that 21 other natural, practically important combinatorial problems — problems arising independently in operations research, graph theory, and scheduling — are also NP-complete. Karp's 21 problems included:

  • Satisfiability
  • 0-1 Integer Programming
  • Clique (does a graph contain a clique of size k?)
  • Vertex Cover
  • Hamiltonian Circuit
  • Graph Colouring
  • Exact Cover
  • Subset Sum

The web of reductions connecting these problems is one of the most beautiful structures in theoretical computer science. Each NP-complete problem can be transformed into any other in polynomial time. They form a kind of equivalence class at the top of NP — a set of problems that are all, in a deep sense, the same problem wearing different clothes. Today there are thousands of known NP-complete problems.

"The reductions between NP-complete problems are not just a technical trick. They reveal a genuine structural kinship between problems that look completely different on the surface. The travelling salesman and graph colouring and satisfiability — they are all shadows of the same underlying hardness." — Richard Karp, Turing Award Lecture, 1985

The practical consequence: decades of researchers trying to find efficient algorithms for any of these problems have failed. Not because of lack of effort or cleverness. The best exact algorithms for NP-complete problems still run in exponential time on worst-case instances. This is the empirical evidence — not a proof, but a strong signal — that they are genuinely hard.

WHY IT'S SO HARD TO PROVE

If P ≠ NP — as nearly everyone believes — why hasn't anyone proved it? The answer is that the proof community has repeatedly run into fundamental barriers that rule out entire families of proof strategies. These barriers don't tell us the answer. They tell us what techniques cannot work.

Relativisation (1975). Baker, Gill, and Solovay showed that there exist oracles — black-box subroutines — relative to which P = NP, and other oracles relative to which P ≠ NP. This means any proof technique that "relativises" — that works equally well whether or not you have access to the oracle — cannot resolve P vs NP, because it would give contradictory answers depending on the oracle. Most classical proof techniques in complexity theory relativise. The relativisation barrier rules out essentially all diagonalisation-based approaches.

Natural proofs (Razborov-Rudich, 1994). Razborov and Rudich formalised a class of proof strategies called "natural proofs" — roughly, proof techniques that work by exhibiting a combinatorial property that hard functions have and easy functions lack, and which can themselves be computed efficiently. They showed that if sufficiently strong pseudorandom function generators exist (which we believe they do), then natural proofs cannot prove superpolynomial lower bounds for circuits. This rules out another enormous category of approaches that had been the dominant paradigm in circuit complexity.

Algebrisation (Aaronson-Wigderson, 2009). The few proof techniques that had escaped the relativisation barrier — notably the IP = PSPACE proof and the PCP theorem — used algebraic extensions of problems rather than just oracle access. Aaronson and Wigderson showed that these techniques also hit a barrier: they cannot resolve P vs NP either, because there are algebrising oracles relative to which P = NP and others relative to which P ≠ NP.

These three barriers together — relativisation, natural proofs, algebrisation — cover almost every proof technique we know how to use in complexity theory. They don't prove P ≠ NP is unprovable. But they establish that a proof will require genuinely new mathematics, ideas that fall outside every major paradigm developed in the last fifty years.

We cannot currently prove that any problem requires more than linear time to solve on a multi-tape Turing machine. The P vs NP problem asks for a superpolynomial lower bound. We cannot even prove a quadratic lower bound unconditionally for any natural problem. The gap between what we want to prove and what we can prove is not a small one — it is a chasm. P vs NP sits on the far side.

WHAT MOST RESEARCHERS BELIEVE

The informal consensus in theoretical computer science is essentially unanimous: P ≠ NP. Surveys of the community consistently find more than 80–90% of respondents believe the answer is no. Some prominent researchers put it higher.

"I'm 99.9% confident that P ≠ NP. If P = NP, it would be the most incredible and surprising result in the history of science. I think nature is simply not that generous." — Scott Aaronson, Professor of Computer Science, UT Austin

The evidence for P ≠ NP is not a proof. It is a convergence of signals:

  • Empirical failure. Decades of brilliant researchers — motivated by the Clay prize, by practical applications, by academic ambition — have tried to find efficient algorithms for NP-complete problems and failed. The best known algorithms for SAT, travelling salesman, and graph colouring still run in exponential time on worst-case instances. This failure is itself evidence, though not proof.
  • Structural intuition. Problems in P have a characteristic feel — they exploit some structure in the problem (linearity, monotonicity, matroid properties, polynomial algebra) that allows efficient solution. NP-complete problems in their worst case appear to require exhaustive search over an exponentially large space. The structures feel fundamentally different.
  • Cryptographic assumptions. Modern cryptography is built entirely on assumptions that certain problems are hard — that factoring, discrete log, and their relatives are not in P. These assumptions have held against sustained, motivated attacks for decades. If P = NP, every cryptographic hardness assumption would collapse simultaneously.
  • Philosophical argument. P = NP would mean that finding is never harder than verifying. At a deep level, this seems to violate an intuition about creativity and search: that discovering a proof, a composition, a design is genuinely harder than checking one. Whether this intuition is reliable is itself a hard question.

But intuition, empirical failure, and philosophical plausibility are not a proof. The history of mathematics is full of conjectures that seemed obviously true for a century before being disproved. "Everyone believes it" is not a proof. This is precisely what makes the problem so unsettling and so fascinating.

P=NP WOULD MEAN

It is worth taking the P = NP scenario seriously rather than dismissing it as obviously impossible. If a polynomial-time algorithm for SAT were discovered tomorrow — even one that ran in time n¹⁰⁰⁰, technically polynomial but practically useless — the implications for the theoretical landscape would be immediate and complete. And it is possible, at least in principle, that a practical polynomial-time algorithm exists. What world would that create?

Cryptography must be entirely rebuilt. Every public-key cryptographic system currently in use — RSA, elliptic-curve, Diffie-Hellman — would be broken. Post-quantum cryptography, which is already being deployed in anticipation of quantum computers, would also be broken if P = NP (since those problems are also NP-hard). We would need cryptography based on some other foundation — information-theoretic security, perhaps, which exists but requires key material as long as the message. The internet as we know it would require fundamental re-engineering.

Mathematical discovery becomes automated. Verifying a mathematical proof is in NP — given a proof and a theorem, checking whether the proof is valid is polynomial. If P = NP, finding proofs is polynomial too. A computer could, in principle, search for proofs of open mathematical conjectures — the Riemann Hypothesis, Goldbach's conjecture, whatever you like — and find them as efficiently as it could verify them. The boundary between "open problem" and "solved problem" would collapse.

Creative work becomes optimisation. Art, music, protein design, drug discovery, engineering optimisation — all of these involve finding a solution among a vast combinatorial space that satisfies constraints and maximises quality. Many of these problems are NP-hard. If P = NP, they become tractable. A system could generate the optimal drug molecule, the optimal bridge design, the optimal musical composition for a given emotional profile — not approximately, but exactly, in polynomial time.

The value of human insight collapses in a very specific domain. Wherever human expertise currently consists of navigating complex combinatorial search spaces — legal reasoning over case space, strategic planning, scientific hypothesis generation — the algorithmic approach would match or exceed it. This wouldn't make humans obsolete in every sense, but it would fundamentally change what kinds of thinking are uniquely human versus what can be automated.

Scott Aaronson has pointed out that P = NP with a practical (not merely polynomial in theory) algorithm would be among the most transformative events in human history — more consequential than the industrial revolution in terms of intellectual disruption. The fact that we consider this possibility remote does not mean we should consider it lightly.

I come back to P vs NP not because I expect to solve it — I don't — but because living with open questions of this kind does something useful to how you think. The problem has been studied for over fifty years by some of the sharpest minds in the history of mathematics and computer science. The barriers to proof are not obstacles waiting for the right clever trick. They are deep structural features of mathematical knowledge itself: statements about what kinds of arguments can and cannot work. Engaging with them seriously is a lesson in epistemic humility.

There is something I find genuinely beautiful in the fact that a question this simple — if you can check, can you find? — opens into this depth. The question is not just about algorithms. It is about the relationship between discovery and verification, between creativity and confirmation. It asks whether the universe is the kind of place where finding things is really harder than recognising them, or whether that difficulty is an illusion we haven't yet seen through.

We don't know. That's the honest answer. And the honest answer is, sometimes, the most interesting thing you can say.
